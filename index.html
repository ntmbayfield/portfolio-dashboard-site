Nonprofit Fundraising Analytics

Dashboard Portfolio

A suite of reporting dashboards built for a nonprofit development office — annual performance, donor retention, campaign goal tracking, and weekly gift reporting.

This site duplicates a recent project I completed to produce a set of executive-level reporting dashboards for a nonprofit CEO and Board of Directors, built on top of an extensive cleanup of the last three fiscal years of fundraising data. All donor and gift data displayed is dummy data — every name, ID, amount, date, campaign, appeal, fund, and revenue figure was randomly generated for a fictional organization, "Northgate Youth Foundation." No real constituent records or organizational financials appear anywhere on this site.

The dashboard visualizations here are the same ones used in the production dashboards — same charts, same tables, same metrics, same interactions. Only the data behind them was swapped. The process used to preserve legacy data and store the cleaned gift data is real, as is the automation: the scheduled pull from Raiser's Edge, the triggered build of each new weekly gift report, and the automatic update to this index page adding a card for it all reflect what was actually implemented.

The problem

Fundraising revenue was reported out of Raiser's Edge NXT, but the campaign, appeal, and fund values behind those numbers had accumulated years of inconsistent attribution. Gifts of the same type were coded to different campaigns across fiscal years, some records were missing campaign, appeal, or fund entirely, and some coding actively misrepresented the gift — an event ticket purchase credited against a monthly recurring giving commitment, for example. Any year-over-year comparison was measuring coding drift as much as fundraising performance, which made it impossible to answer leadership's actual questions about budget, program return, and staffing.

Establishing the rules first

The work ran in two parts. First, a governed campaign structure adopted at the start of FY27 — the campaign list, a written definition of each campaign, the rules governing which campaign a gift belongs to, and a hierarchy for gifts that could fall into more than one. That structure was signed off by the CEO, the Director of Development, the Gift Processor, and the Accounting and Finance team, the four parties whose work depends on those definitions holding. The most consequential rule was redefining Major Gifts: a gift belongs there not because of its dollar amount, but because it is the product of a development officer's work — a submitted proposal, a verbal ask, a gift following a campus tour — with CRM evidence of prior engagement to support it. That reframes Major Gifts from a size bucket into a measure of relationship-driven fundraising, which is what makes portfolio return measurable at all.

Normalizing without overwriting

Second, three fiscal years of historical gift data normalized against that structure. I exported five fiscal years from Raiser's Edge — roughly 60,000 rows — as an untouched control dataset to run reconciliation checks against, then segmented each fiscal year into its own file, flagged every record missing campaign, appeal, or fund data, and worked through the patterns revealing how gifts had actually been attributed each year, as distinct from what policy said. Rather than overwrite anything, I created three parallel attributes — Normalized Campaign, Normalized Appeal, and Normalized Fund — each holding either the original value where attribution was already correct or the corrected value under the FY27 rules, with a comment field recording the basis for the call. Records the evidence couldn't resolve were marked as judgment-based rather than silently absorbed, and leadership accepted a stated ±2% margin on fiscal-year figures in exchange for a complete dataset to plan from.

Automating the reporting cycle

Reporting was also moved off request and onto a schedule. A weekly Power Automate flow writes a gift detail file to SharePoint; that file landing triggers a second automation that builds the week's dashboard, recalculates fiscal-year-to-date totals across every prior week, and adds a card for the new report to this page — no one touches the HTML. A documented manual export procedure covers failed runs and off-cycle requests, producing an identical file in the same folder so it feeds the same build rather than a parallel one. Each dashboard is a single self-contained HTML file with data embedded as JSON and Chart.js bundled inline: no server, no database, trivial to host. The Dashboard Reference documents every metric definition, filtering rule, data relationship, and the export SOP.

What this work involved

  • Designing donor-movement logic (New / Retained / Recaptured / Lapsed / LYBUNT / SYBUNT) from gift-level data keyed on constituent ID across fiscal years.
  • Reconciling a campaign reclassification project and quantifying its effect on reported revenue year over year.
  • Building a repeatable weekly reporting pipeline with cumulative fiscal-year-to-date rollups by campaign, appeal, and fund.
  • Writing the metric definitions, filtering rules, and standard operating procedures so the reports can be reproduced by someone else.
